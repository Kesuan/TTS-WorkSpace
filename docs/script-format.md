# 对白脚本格式 v1

> 多角色对白脚本（有声书 / 广播剧 / 配音生产）的输入格式。解析器在 🚧 M1 实现；本文档为**格式契约**，实现与测试以本文档为准。

## 示例

```
# 第一章
## 雨夜

// 注释行（行首 //）
旁白: 站台的灯闪了两下。
阿岚: (低沉)[叹气] 又是这样的雨……
    他把伞往前递了递。
    雨点砸在伞面上，噼啪作响。
小满: 哥，你还在等那班车吗？
没有角色前缀的段落默认归入「旁白」。
```

## 语法规则

| 规则 | 说明 |
| --- | --- |
| 编码 | UTF-8（LF 或 CRLF 均可） |
| 角色行 | `角色名: 台词`；冒号兼容半角 `:` 与全角 `：` |
| 角色名 | ≤ 24 字符；不可包含 `:` `：` `[` `]` `/`；解析时去除首尾空白 |
| 续行 | 紧跟角色行之后的非空、非角色行、非标题行 —— 追加到上一条台词；中文默认无连接符，英文可用 `join_with_space` 配置（🚧） |
| 章节 | `# 标题`（可选，用于分组与导出目录） |
| 场景 | `## 标题`（可选，同上） |
| 其他标题 | `###` 及以上视为注释，忽略 |
| 注释 | 行首（去空白后）为 `//` 的整行；行内 `//` 不处理（避免误伤 URL） |
| 空行 | 仅作可读分隔，不打断后续解析 |
| 行内标签 | `(风格)`（通常置于台词开头）与 `[音频标签]`（任意位置）**原样保留**，直接透传给 MiMo API |
| 旁白 | `旁白:` 显式写法；无角色前缀的正文段落默认归入「旁白」（可配置为忽略，🚧） |
| 行数上限 | 无硬限制；建议单文件 ≤ 1MB |

## 稳定行 ID

行 ID 由内容派生，保证“重导入不炸、改动可追踪”：

```
id = "L" + sha1(章节 | 场景 | 角色 | 规范化文本)[0:8]
```

- 规范化文本：去除首尾空白、合并连续空白（行内标签保留原样）。
- 同文本重复行（同一章节+场景+角色下）：追加序号后缀 `-2`、`-3`。
- **文本改动的行视为新行**：旧行标记为 `removed`，其 takes 保留不删除（导出默认排除）。
- 重导入输出 diff：`added` / `removed` / `changed` / `unchanged`（🚧 M1）。

## 行级参数覆盖（非脚本语法）

需要给单行指定不同音色 / 风格时，**不要**改脚本语法，而是写入 `lines.json`（`tts line set`，🚧 M1）：

```bash
tts line set --line L3f2a9c01 --style "(低语) 我没事，真的。"
```

原则：脚本保持“可读的创作文本”，工程参数走项目元数据（可回滚、可审计、Agent 可控）。

## 解析报告（`tts project import --json`，🚧 M1）

```json
{
  "ok": true,
  "data": {
    "script": "script/chapter1.txt",
    "counts": { "lines": 42, "roles": 3, "scenes": 2, "narrator_lines": 5 },
    "roles": ["阿岚", "小满", "旁白"],
    "unbound_roles": ["小满"],
    "warnings": [
      { "line": 7, "code": "W_NARRATOR_FALLBACK", "message": "无角色前缀，已归入旁白" }
    ],
    "diff": { "added": 42, "removed": 0, "changed": 0, "unchanged": 0 }
  }
}
```

- `unbound_roles`：尚未绑定音色的角色（批量生成前必须先绑定，`tts role bind`）。
- 解析失败（编码 / 角色名非法等）返回 `E_PARSE_SCRIPT`（退出码 1），`details` 带 `file:line:col`。
